# Consolidation contract

This contract defines how `inorganic`, `organic`, and `structure` converge into one consumer-ready chemistry knowledge release without changing package-local ownership.

## 1. Source ownership and immutability

- Source packages remain canonical for their own released records.
- Consolidation reads source-package public/released boundaries and writes only under `packages/consolidated/**`.
- Corrections discovered during consolidation are recorded as integration findings or mappings first; source data is changed only by its owning workstream or after explicit ownership reassignment.
- Published `packages/structure/` `structure_id` values are reused as-is and are never regenerated by consolidation.

## 2. Consolidated identity

A consolidated chemical entity receives one stable integration ID that is persisted in the release crosswalk.

Rules:

- package-local IDs remain provenance anchors and are never discarded;
- names, formulas, aliases, slugs, and external database IDs are attributes or matching evidence, not the global identity itself;
- once a consolidated ID is published, later releases preserve it even when labels, aliases, provenance, or classifications improve;
- one consolidated entity may map to multiple source IDs from different packages;
- uncertain matches remain separate with an explicit unresolved mapping instead of being merged by guesswork.

The crosswalk is the canonical owner of `source package ID -> consolidated ID` mappings.

## 3. Entity convergence

### Species

The consumer species layer unifies:

- inorganic `ion`;
- inorganic `substance`;
- organic `substance`.

The integration representation preserves at minimum:

- stable consolidated ID;
- source IDs;
- entity kind (`ion` or `substance`);
- Chinese and English names where available;
- formula;
- integer charge;
- elemental composition when source-supported;
- aliases;
- teaching priority;
- source verification/review state;
- provenance references;
- external IDs;
- optional published Structure link.

No HTML chemistry typography is stored. Formula counts and charge remain structured/plain chemistry data and the application renders subscripts/superscripts.

### Structure

Structure remains a separate entity. A species may link to zero or one preferred published Structure record plus additional explicit structure relations when future requirements justify them.

Matching evidence is ranked as follows where applicable:

1. explicit package cross-reference;
2. matching authoritative external identifier;
3. matching published InChIKey for molecular entities;
4. reviewed formula + charge + entity-scope match for simple ions/formula units.

Formula-only matching is never sufficient for isomeric molecular substances.

### Reaction and other knowledge entities

Reaction remains a first-class entity and is never collapsed into pairwise species edges.

Organic reactions can enter the consolidated release once all participant references resolve through the species crosswalk. Inorganic reactions are added only after the inorganic owner publishes an eligible reaction boundary.

Concept, Phenomenon, Experiment, FunctionalGroup, and taxonomy records retain their own stable entity types; consolidation maps references rather than flattening them into species fields.

## 4. Provenance merge

Consolidation is additive:

- source-package provenance is retained;
- source-specific review/verification status is preserved;
- the consolidated record adds integration provenance describing which source records produced the merged view;
- disagreement between sources is represented explicitly and does not silently overwrite evidence;
- a consumer projection may select a preferred published value only when a deterministic policy or reviewed decision exists.

## 5. High-school teaching projection

Chemical facts and teaching/UI projection are separate responsibilities.

The consolidated teaching projection may contain:

- `teaching_priority`: `core | common | extended`;
- one primary high-school category;
- zero or more orthogonal teaching/filter tags;
- search keywords/normalized aliases;
- default palette ranking metadata.

Initial primary categories for species are:

- `elemental_substance`
- `cation`
- `anion`
- `acid`
- `base`
- `salt`
- `oxide`
- `organic`
- `other`

Properties such as `gas`, `precipitate`, `sparingly_soluble`, `strong_electrolyte`, `weak_electrolyte`, and `volatile` are tags/behavioral facts, not competing primary categories.

The projection may evolve without changing consolidated chemical identity.

## 6. Search projection

Search is generated from canonical data rather than maintained as duplicate truth.

Searchable forms may include:

- Chinese name and aliases;
- English name and aliases;
- plain formula (`SO4`);
- rendered-equivalent normalized formula tokens;
- external identifiers when useful;
- high-school category and tags.

Search normalization must not mutate canonical names/formulas.

## 7. Equation Lab / Reaction Builder projection

The data release supports structured composition and candidate lookup without encoding user behavior into the chemistry dataset.

System projection can provide:

- common ions/species by teaching priority;
- category tabs such as elemental substances, cations, anions, acids, bases, salts, oxides, and organic species;
- mode-aware suitability/ranking for molecular, ionic, and net-ionic equation workflows;
- deterministic composition/electrical-neutrality evidence where chemically valid;
- `0..N` candidate species results for a composition/query context.

Candidate lookup is plural by design. Ambiguous chemistry (for example multiple oxidation states or multiple compounds for the same element set) must return multiple reviewed candidates rather than inventing a single answer.

Runtime personalization stays outside this repository:

- pinned species;
- manual category/item order;
- recent usage;
- usage-frequency ranking;
- hidden items;
- custom trays.

The application may combine these runtime signals with the package's default teaching ranking.

## 8. Duplicate resolution

A merge requires enough identity evidence for the entity type.

- Exact package IDs only identify records inside their source package.
- External IDs and Structure identifiers are strong evidence where semantics match.
- Formula + charge + composition can identify many simple inorganic ions/formula units but is not globally unique for molecular substances.
- Chinese/English labels are supporting evidence only.
- Organic structural isomers remain distinct even when formulas are identical.
- Disputed or ambiguous records are emitted to an unresolved mapping report and remain separate until reviewed.

## 9. Consumer release shape

The first release should converge to a small stable set of consumer artifacts rather than mirror each package directory:

- species records;
- source-ID crosswalk;
- species-to-Structure links;
- teaching/search projection;
- eligible reactions and their participant references;
- provenance/source registry projection;
- unresolved integration findings;
- release manifest and validation report.

Exact serialization/schema files are frozen only after the inorganic package is ready and all three source boundaries have been compared against this contract.

## 10. Release gates

A consolidated release is publishable only when:

1. inorganic reports `READY_FOR_CONSOLIDATION`;
2. organic v0.1 and published Structure inputs remain traceable and unchanged;
3. every published consolidated record resolves back to at least one source record;
4. source-ID crosswalk IDs are unique and stable;
5. Reaction participants resolve to consolidated species IDs without reducing Reaction to pairwise edges;
6. published Structure references point to existing published Structure records;
7. formula/charge/composition consistency checks pass where applicable;
8. duplicate detection leaves no silently merged ambiguous molecular records;
9. teaching/search projection contains no runtime user preference state;
10. a machine validation run produces a release report with zero blocking errors.

Until these gates pass, `packages/consolidated/` is an active integration workstream rather than a published data release.
